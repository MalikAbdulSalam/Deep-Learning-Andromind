```
1. What is YOLO?

YOLO stands for You Only Look Once. It is a family of real-time object detection models used to identify objects and their locations in images and video.

For example, a PPE detection system might detect:

Person Helmet Vest Mask Gloves

The model produces:

  • Object class
  • Bounding box
  • Confidence score
Example: A YOLO model might detect a helmet with a confidence score of 0.94 and draw a bounding box around it.
``` 

```
3. Define Your Classes

Before collecting and annotating data, clearly define what the model needs to detect.

Example: PPE Detection

``` 
0 = person
1 = helmet
2 = vest
3 = mask
4 = gloves
```
Class IDs start from 0. Do not randomly change class IDs after annotation.

For three classes:

``` 
0 → person
1 → helmet
2 → vest
```

4. Collect Images

Collect images that represent the real environment in which your model will operate.

Include variations in:

  • Lighting
  • Camera angle
  • Object size
  • Distance
  • Background
  • Occlusion
  • Indoor and outdoor environments
  • Different object appearances
  • Different camera resolutions
Do not assume that 1,000 nearly identical frames are equivalent to 1,000 diverse images.

5. Annotate Images

Object detection requires bounding-box annotations. Common annotation tools include:

  • LabelImg
  • CVAT
  • Roboflow
  • Label Studio

For an image:

``` 
worker.jpg
```

There should be a corresponding label file:

``` 
worker.txt
```

The image and label should have the same base filename.

``` 
image001.jpg
image001.txt

image002.jpg
image002.txt
```

6. YOLO Label Format

YOLO uses the following annotation format:

``` 
class_id x_center y_center width height
```

Example:

``` 
0 0.512 0.438 0.245 0.512
1 0.530 0.215 0.120 0.160
```
Value Meaning
class_id Object class number
x_center Normalized center X coordinate
y_center Normalized center Y coordinate
width Normalized bounding-box width
height Normalized bounding-box height
Bounding-box coordinates are normalized between 0 and 1.
``` 

```
8. Train / Validation / Test Split

A common dataset split is:

Dataset Typical Percentage Purpose
Training 70–80% Learning model parameters
Validation 10–20% Monitoring model performance
Testing 10% Final evaluation
When extracting many frames from the same video, avoid randomly putting nearly identical frames into both training and validation.
``` 

```
12. Select a YOLO Model

YOLO model families commonly provide different model sizes. Smaller models generally require fewer resources, while larger models can provide stronger accuracy at higher computational cost.

For initial experiments, a small model is a good starting point.

``` 
from ultralytics import YOLO

model = YOLO("yolo26n.pt")
```
Model filenames depend on the Ultralytics version you install. Use a model supported by your installed release.

13. Train the Model

Python Training

``` 
from ultralytics import YOLO

model = YOLO("yolo26n.pt")

results = model.train(
    data="data.yaml",
    epochs=100,
    imgsz=640,
    batch=16,
    device=0,
    workers=4
)
```

Important Parameters

Parameter Purpose
data Dataset configuration file
epochs Number of training epochs
imgsz Training image size
batch Number of images processed per batch
device GPU or CPU device
workers Data-loading workers

Command Line Training

``` 
yolo detect train model=yolo26n.pt data=data.yaml epochs=100 imgsz=640
```

For a specific NVIDIA GPU:

``` 
yolo detect train model=yolo26n.pt data=data.yaml epochs=100 imgsz=640 device=0

        ├── confusion_matrix.png

        ├── F1_curve.png
        └── ...
```

best.pt

The best-performing checkpoint according to the validation metrics tracked during training.

last.pt

The checkpoint from the final training epoch.

For most inference and deployment workflows, start by evaluating best.pt.

15. Training Metrics

Precision

Precision measures how many predicted detections are correct.

Precision = TP / (TP + FP)

Recall

Recall measures how many of the actual objects were detected.

Recall = TP / (TP + FN)

IoU

Intersection over Union measures the overlap between the predicted bounding box and the ground-truth bounding box.

IoU = Intersection Area / Union Area

mAP

Mean Average Precision is a major object-detection evaluation metric.

  • mAP50: evaluation at IoU threshold 0.50
  • mAP50-95: evaluation across multiple IoU thresholds
``` 

```
19. Webcam Detection

``` 
from ultralytics import YOLO

model = YOLO("best.pt")

model.predict(
    source=0,
    show=True,
    conf=0.5
)
```

Here source=0 usually represents the default webcam.

OpenCV Real-Time Example

``` 
import cv2
from ultralytics import YOLO

model = YOLO("best.pt")

cap = cv2.VideoCapture(0)

while True:

    ret, frame = cap.read()

    if not ret:
        break

    results = model(frame, verbose=False)

    annotated = results[0].plot()

    cv2.imshow("YOLO Detection", annotated)

    if cv2.waitKey(1) & 0xFF == ord("q"):
        break

cap.release()
cv2.destroyAllWindows()
```

20. Confidence Threshold

The confidence threshold controls how confident the model must be before returning a detection.

``` 
model.predict(
    source="image.jpg",
    conf=0.5
)
```
Confidence General Effect
0.25 More detections, potentially more false positives
0.50 Balanced starting point
0.70 More selective detections

21. Common Dataset Problems

Problem 1 — Missing Labels

``` 
image001.jpg
```

but there is no:

``` 
image001.txt
```

This can indicate a dataset preparation problem, depending on whether the image is intended to contain annotated objects.

Problem 2 — Incorrect Class IDs

``` 
names:
  0: helmet
  1: person
```

but a label contains:

``` 
2 0.5 0.5 0.2 0.3
```

Class 2 does not exist in the YAML above.

Problem 3 — Incorrect Bounding Boxes

Bounding boxes should accurately cover the intended object. Incorrect annotations teach the model incorrect visual patterns.

Problem 4 — Class Imbalance

``` 
person = 10,000 objects
helmet = 500 objects
```

The model receives much more training information about one class than the other.

22. Dataset Quality Checklist

  • ✓ Images are readable
  • ✓ Labels exist where required
  • ✓ Image and label filenames match
  • ✓ Class IDs are correct
  • ✓ Bounding boxes are correct
  • ✓ No corrupted images
  • ✓ No unnecessary duplicates
  • ✓ Train/validation/test split is correct
  • ✓ data.yaml is correct
  • ✓ Number of classes is correct
  • ✓ Class names are correct

23. Avoid Data Leakage

Data leakage happens when highly similar data appears in both training and validation/testing datasets.

For example, if one video produces:

``` 
frame001
frame002
frame003
...
frame1000
```

randomly splitting these frames can put almost identical scenes into both training and validation.

For video-based datasets, consider splitting by:

  • Video
  • Scene
  • Camera
  • Recording session

24. How to Improve a YOLO Model

If the model performs poorly, do not immediately increase the number of epochs.

``` 
Dataset Quality
      ↓
Annotations
      ↓
Class Balance
      ↓
Image Diversity
      ↓
Image Resolution
      ↓
Model Size
      ↓
Training Parameters
```
More epochs cannot completely compensate for poor annotations or a poorly designed dataset.

Professional Improvement Cycle

``` 
Dataset v1
    ↓
Train
    ↓
Evaluate
    ↓
Find Failure Cases
    ↓
Collect More Images
    ↓
Correct Annotations
    ↓
Dataset v2
    ↓
Train Again
    ↓
Evaluate
    ↓
Deploy
```

27. Complete Training Script

``` 
from ultralytics import YOLO


# ============================================================
# CONFIGURATION
# ============================================================

MODEL = "yolo26n.pt"
DATASET = "dataset/data.yaml"

EPOCHS = 100
IMAGE_SIZE = 640
BATCH_SIZE = 16
DEVICE = 0


# ============================================================
# LOAD MODEL
# ============================================================

model = YOLO(MODEL)


# ============================================================
# TRAIN
# ============================================================

results = model.train(
    data=DATASET,
    epochs=EPOCHS,
    imgsz=IMAGE_SIZE,
    batch=BATCH_SIZE,
    device=DEVICE,
    project="runs",
    name="custom_yolo"
)


print("Training completed.")
