1. Requirements

You need:

  • Google account
  • Google Drive
  • Google Colab
  • YOLO-compatible custom dataset
  • Internet connection
  • GPU runtime in Google Colab

A free Colab GPU may be sufficient for small and medium datasets. For larger datasets, GPU availability and VRAM may vary.

Open Google Drive and create a folder for your project. For example:

A standard YOLO detection dataset should look like this: 

dataset/
│
├── data.yaml
│
├── train/
│   ├── images/
│   │   ├── image001.jpg
│   │   ├── image002.jpg
│   │   └── image003.jpg
│   │
│   └── labels/
│       ├── image001.txt
│       ├── image002.txt

│
├── val/
│   ├── images/
│   │   ├── image101.jpg
│   │   └── image102.jpg
│   │
│   └── labels/
│       ├── image101.txt
│       └── image102.txt

    │   └── image202.jpg
    │
    └── labels/
        ├── image201.txt
        └── image202.txt
Important: Every image should have a corresponding YOLO label file when annotations exist.

4. YOLO Label Format

Each object annotation is stored in a .txt file.

Example:

0 0.512 0.432 0.240 0.310
1 0.720 0.580 0.150 0.220

The format is:

class_id x_center y_center width height

All coordinates are normalized between 0 and 1.

Value Meaning
class_id Object class number
x_center Center X coordinate
y_center Center Y coordinate
width Bounding-box width
height Bounding-box height

14. Train the Custom YOLO Model

Basic training: 

from ultralytics import YOLO

model = YOLO("yolo26n.pt")

results = model.train(
    data=DATA_YAML,
    epochs=100,
    imgsz=640,
    batch=16,
    device=0
)

Recommended training configuration

results = model.train(
    data=DATA_YAML,
    epochs=100,
    imgsz=640,
    batch=16,
    device=0,
    workers=2,
    project="/content/runs",
    name="custom_yolo"
)

Training results will be created under: 

/content/runs/custom_yolo/

15. What Happens During Training?

During training YOLO performs the following process:

  1. Loads training images.
  2. Loads bounding-box labels.
  3. Resizes images.
  4. Applies data augmentation.
  5. Runs the neural network.
  6. Calculates losses.
  7. Updates model weights.
  8. Evaluates the validation dataset.
  9. Saves checkpoints.
  10. Generates training graphs and metrics.

18. Understand YOLO Metrics

Metric Meaning
Precision How many predicted objects are actually correct
Recall How many real objects were successfully detected
IoU Overlap between predicted and ground-truth bounding boxes
mAP50 Mean average precision at IoU threshold 0.50
mAP50-95 Mean average precision across multiple IoU thresholds

31. Change Confidence Threshold

The confidence threshold controls how confident YOLO must be before displaying a detection. 

results = model.predict(
    source="/content/test.jpg",
    conf=0.50
)

Examples:

conf=0.20
conf=0.25
conf=0.50
conf=0.70

A lower value generally produces more detections but can increase false positives. A higher value produces fewer detections but can miss weak detections.

43. Common Problems

Problem 1: CUDA Out of Memory

batch=8

If still insufficient: 

batch=4

You can also reduce imgsz.

Problem 2: data.yaml Not Found

Check the path:

import os

print(os.path.exists(DATA_YAML))
print(DATA_YAML)

If it returns False, correct the Google Drive path.

Problem 3: Labels Not Found

Check that: 

train/images/
train/labels/

val/images/
val/labels/

exist and that image and label filenames match.

Example:

image001.jpg
image001.txt

Problem 4: Wrong Number of Classes

If data.yaml contains: 

names:
  0: helmet
  1: mask
  2: vest

then your class IDs must use: 

0
1
2

Problem 5: Poor Accuracy

Check:

  • Annotation quality
  • Number of training images
  • Class balance
  • Image diversity
  • Lighting conditions
  • Object size
  • Camera angles
  • Background variation
  • Training epochs
  • Image resolution

44. Dataset Quality Checklist

  • ☐ Images are clear enough for the task
  • ☐ Bounding boxes tightly surround objects
  • ☐ No incorrect class IDs
  • ☐ No missing label files
  • ☐ Training and validation images are separated
  • ☐ Test data is kept unseen
  • ☐ All classes are represented
  • ☐ Similar duplicate images are avoided across splits
  • ☐ Different lighting conditions are included
  • ☐ Different object sizes are included
  • ☐ Different backgrounds are included
